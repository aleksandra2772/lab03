# Анализ и моделирование данных предметной области

## 1. Описание предметной области

Предметная область: сервис аренды автомобилей.

Сервис аренды автомобилей предоставляет клиентам автомобили во временное пользование за плату. Компания ведёт парк автомобилей, регистрирует клиентов и оформляет договоры аренды.

Назначение:

Информационная система предназначена для учёта автомобилей парка, клиентов и договоров аренды, а также для поиска свободных автомобилей и контроля их возврата.

Основные процессы:

- ведение парка автомобилей;
- регистрация клиентов;
- поиск доступного автомобиля;
- оформление аренды автомобиля;
- возврат автомобиля;
- хранение истории аренд.

Основные пользователи:

- клиенты сервиса аренды;
- сотрудники сервиса аренды (менеджеры, администраторы).

Основные задачи информационной системы:

- хранение информации об автомобилях парка;
- хранение информации о клиентах;
- учёт статуса автомобиля (доступен, в аренде, на обслуживании);
- поиск автомобилей, доступных на выбранные даты;
- оформление и хранение договоров аренды;
- учёт возврата автомобилей;
- просмотр истории аренд клиента и автомобиля.

## 2. Объекты данных

В предметной области выделены следующие основные объекты данных.

### Клиент

Человек, который арендует автомобиль в сервисе.

Необходимо хранить:

- идентификатор клиента;
- ФИО;
- номер телефона;
- адрес электронной почты;
- номер водительского удостоверения;
- дату регистрации.

### Автомобиль

Автомобиль из парка сервиса, который можно сдать в аренду.

Необходимо хранить:

- идентификатор автомобиля;
- марку;
- модель;
- государственный номер;
- VIN;
- год выпуска;
- класс автомобиля;
- стоимость аренды в сутки;
- статус (доступен, в аренде, на обслуживании).

### Аренда

Информация об оформленной аренде автомобиля клиентом.

Необходимо хранить:

- идентификатор аренды;
- идентификатор клиента;
- идентификатор автомобиля;
- дату и время начала аренды;
- планируемую дату окончания аренды;
- стоимость аренды;
- статус аренды (активна, завершена).

### Возврат автомобиля

Информация о возврате автомобиля после окончания аренды.

Необходимо хранить:

- идентификатор возврата;
- идентификатор аренды;
- дату и время фактического возврата;
- пробег при возврате;
- состояние автомобиля;
- сумму штрафа или доплаты (если есть).

### Платёж

Информация об оплате аренды клиентом.

Необходимо хранить:

- идентификатор платежа;
- идентификатор аренды;
- дату платежа;
- сумму;
- способ оплаты.

## 4. Классификация данных

Выделенные данные можно классифицировать по их назначению и типу.

| Категория данных | Примеры | Назначение |
|---|---|---|
| Текстовые | ФИО клиента, телефон, email, номер водительского удостоверения, марка, модель, госномер, VIN, состояние автомобиля при возврате | Хранение текстовой информации об объектах |
| Числовые | идентификаторы, год выпуска, стоимость в сутки, стоимость аренды, пробег, сумма платежа, штраф | Хранение числовых значений |

| Логические | отсутствуют в текущей модели | В текущей модели данные типа «да/нет» не используются |
| Справочные | класс автомобиля, статус автомобиля, статус аренды, способ оплаты | Хранение значений из определённого набора |
| Вычисляемые | стоимость аренды, сумма штрафа или доплаты | Значения могут быть рассчитаны на основе других данных (количество суток аренды, стоимость в сутки, фактическая дата возврата) |

## 5. Связи между объектами

Между объектами предметной области были определены следующие связи.

### Клиент - Аренда

Тип связи: один ко многим (1:N).

Один клиент может оформить несколько аренд. Каждая аренда оформляется одним клиентом.

### Автомобиль - Аренда

Тип связи: один ко многим (1:N).

Один автомобиль может сдаваться в аренду много раз (в разное время). Каждая аренда относится к одному автомобилю.

### Аренда - Возврат автомобиля

Тип связи: один к одному (1:1).

По каждой завершённой аренде оформляется один возврат автомобиля. Каждый возврат относится к одной конкретной аренде.

### Аренда - Платёж

Тип связи: один ко многим (1:N).

Аренда может оплачиваться несколькими платежами (например, предоплата и доплата при возврате). Каждый платёж относится к одной аренде.

## 6. Концептуальная модель данных

На схеме отражены следующие связи:

- Клиент 1:N Аренда;
- Автомобиль 1:N Аренда;
- Аренда 1:1 Возврат автомобиля;
- Аренда 1:N Платёж.

## 7. Оценка качества исходных данных

После построения концептуальной модели была выполнена оценка полноты и качества данных.

### Достаточно ли объектов выделено?

Да. Выделенные объекты описывают основные данные, необходимые для учёта клиентов, автомобилей, аренд, возвратов и платежей.

### Отсутствуют ли важные сущности?

Для рассматриваемой модели основных сущностей достаточно. При дальнейшем развитии системы могут быть добавлены сотрудники, страхование, штрафы, филиалы и техническое обслуживание автомобилей.

### Все ли необходимые атрибуты определены?

Для построения концептуальной модели определены основные атрибуты каждого объекта. При реализации реальной информационной системы набор атрибутов может быть расширен.

### Имеются ли дублирующиеся данные?

Явного дублирования данных в модели нет. Информация о клиентах, автомобилях, арендах, возвратах и платежах хранится в отдельных объектах и связывается между собой. Стоимость аренды и штраф можно вычислить, но их целесообразно хранить, так как они фиксируют условия конкретной аренды на момент оформления.

### Достаточно ли информации для дальнейшего проектирования информационной системы?

Да. Выделены основные объекты, их атрибуты и связи. Полученная модель может использоваться как основа для дальнейшего проектирования базы данных.
